# 말뚝 기능 기획 먼저

코드를 한 줄도 쓰기 전에 아래 1페이지 명세를 사용자에게 보여주고 "진행" 확인을 받는다. 사용자는 휴대폰으로 읽으니 짧게, 표 위주로.

## 1. 먼저 읽을 것
- `docs/ROADMAP.md`에서 해당 버전 부분
- 관련 엔진 파일(`game/src/engine/`)과 화면 파일(`game/src/ui/`)
- `CLAUDE.md`의 "절대 지킬 것"과 "디자인 원칙"

## 2. 명세 형식 (이 순서, 이 제목)
1. **한 줄 목표**: 이 기능으로 사용자가 무엇을 느끼게 되나
2. **규칙**: 표로. 숫자는 구체적으로(확률·보상·기간·인원)
3. **화면**: 바뀌는 화면 목록과 각 화면에 새로 보이는 것 한 줄씩. 기존 클래스 재사용 여부
4. **엔진·데이터**: 바뀌는 파일, 새 필드. GameState나 저장 형식이 바뀌면 옛 저장과의 호환 방법
5. **서버**: Supabase 변경이 있으면 SQL 요약과 "SQL 먼저 Run 필요" 표시. 없으면 "없음"
6. **같은 출발선 영향**: 오늘의 기수·우리 기수·대항전에서 모두에게 같은지, rollSeed만 쓰는지
7. **밸런스 영향**: 장군 비율에 영향이 있으면 어떤 시뮬로 확인할지
8. **위험**: 실제 부대·사건 연상, 개인정보, 비용
9. **작업량**과 **정할 것**(괄호 안에 추천)

## 3. 확인 후
- 사용자가 고친 부분을 반영해서 바로 구현한다. 명세와 다르게 만들게 되면 이유를 한 줄로 알린다.
- 구현 뒤에는 malttuk-qa → (밸런스 영향이 있으면) malttuk-balance 순서로 확인한다.
